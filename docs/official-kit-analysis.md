以下地址是该哈希二进制的首选 VA，不是文件偏移，也不是其他版本通用地址。

## 模式分支

`0x415970` 读取 0xa8 字节头，检查版本字节 1、1；随后依次读取
page_count × 0x1c 和 frame_count × 0x20 的表，与本项目 Ogg 起点计算一致。
头存于对象 +0x18，模式从对象 +0x40 复制到 +0xc4，即文件偏移 0x28。

`0x417010` 对对象 +0xc4 仅有三个显式分支：

| 值 | OMVLib 行为 | 与 OMVTool 对照 |
|---|---|---|
| 0 | 三平面依次写入内存 B、G、R，A=255 | 一致；输出 RGBA 时需反转颜色平面顺序 |
| 1 | 同上，另从三个平面 H 行之后读取 alpha | 一致，分段长度为 ceil(H/3)，最后一段取剩余行 |
| 2 | 用三个平面组成 Y/U/V 索引查 RGB 表 | 全范围 BT.601 类矩阵解释得到直接依据 |

`0x417380` 是显示 alpha 的辅助路径：0/2 输出白色，1 读取同样三段 alpha。
它不是第四种文件模式。未知模式在这些函数中没有对应输出分支；工具继续明确
拒绝未知模式比输出未初始化画面合适。**本次没有发现 0/1/2 之外的模式，
但没有证明所有 Siglus 版本都只存在三种模式。**

## 色彩与取整

`0x416eb0` 生成 256³ 项 BGRA 查找表。设 u=U−128、v=V−128：

```text
R = trunc(Y + 1.402*v)
G = trunc((Y - 0.34414*u) - 0.71414*v)
B = trunc(Y + 1.772*u)
每个通道随后截断到 [0,255]；A=255。
```

常量分别在 0x697088、0x697068、0x697078、0x697090，以 IEEE binary64 保存。
0x416f4c、0x416f64、0x416f85 的 `CVTTSD2SI` 明确向零截断。
没有 Y−16 或 255/219 缩放，因此是全范围解释，不是有限范围 BT.601。
`0x417010` 按 `(Y<<16)|(U<<8)|V` 查表，索引和通道顺序相互吻合。

本项目原 RGBA 重建采用 float32 和最近取整；现将默认 full/601 改为
binary64、上述系数和截断。例如 YUV=(100,129,130) 应得到 RGB=(102,98,101)，
原最近取整会得到 (103,98,102)。显式 limited/709 等覆盖仍保留标准转换规则。

此修正作用于 **mode 2 的 RGBA 管道重建**。MP4 路径仍由 FFmpeg 直接做
YUV 矩阵/范围转换，避免 RGB 中转和额外裁剪；FFV1 路径仍保留原始解码 YUV
样本。不能把这些输出称为逐像素复现 OMVLib 的 RGB 查表、显卡合成和游戏显示。

## 手册与音频

SiglusManual/SiglusManual.txt 使用 CP932。约第 10330–10398 行说明 OMV
由 OMVPack 制作，2011-08-25 / 引擎 1.0.9.8 增加无透明度 RGB 视频支持，
并将不能播放声音列为 OMV 的限制。该手册具有历史版本背景，不能外推全部新版本。

因此游戏素材没有内嵌音轨是合理的，与先前样本观察一致。OMVTool 对合法内嵌
Ogg 音轨的保留属于转换器能力；合成音频测试不证明官方引擎会播放它们。
